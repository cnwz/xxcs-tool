
# 发布流程

## 准备（首次）

1. 在 `build/` 目录执行 `npm install`
2. 修改 `src/js/module/Core.js` 里的 `this.repo`
3. 在 GitHub / Gitee 建好仓库
4. 在 `git/` 目录 `git clone` 仓库（可选，用于自动 commit）

## 每次发布

### 1. 改代码

改 Core / 模块 / 任何东西。

### 2. 改版本号

`src/index.html` 和 `src/debug.html` 的：

```html
<meta name="app-version" content="1.0.0">
```

改成新版本号。

**递增规则**：

| 改动                | 递增                   |
| ------------------- | ---------------------- |
| 改方法签名 / 删方法 | A 位（1.0 → 2.0）     |
| 加方法 / 加功能     | B 位（1.0.0 → 1.1.0） |
| 修 bug / 优化       | C 位（1.0.0 → 1.0.1） |

### 3. 跑脚本

```bash
cd build
node 发布.js
```

**选项**：

- `--force`：Core.js 变动时强制继续
- `--skip-git`：跳过 git 同步

### 4. 脚本输出

- `dist/二维码及库位优化工具_v{版本}.zip`
- `docs/wiki/更新/{日期}.md`（草稿）
- `git/` 目录里本地 commit
- 控制台打印待办

### 5. 打 tag 并推送

```bash
cd git
git push origin main
git push github main
git tag v1.0.1
git push origin v1.0.1
git push github v1.0.1
```

### 6. 上传 Release 附件

- Gitee：`dist/二维码及库位优化工具_v1.0.1.zip`
- GitHub：同上

### 7. 填 Wiki 更新说明

- 打开 `docs/wiki/更新/{日期}.md`
- 补充"本次改了什么"
- 复制到 Gitee Wiki 的"更新/{日期}"页面

## 脚本不做的事

- 不自动 push git（只本地 commit）
- 不自动上传 Release
- 不自动写 Wiki
- 不自动打 tag

**手动做这四件事。**

## Core.js 变动处理

脚本会对比 `Core.js` 的 MD5。**变动则终止发布**，除非 `--force`。

**原因**：Core 锁死，改 Core 意味着大版本升级，所有模块要整体更新。

**如果确认是加大版本**：

1. 改 `meta` 版本号到 A 位（如 1.5 → 2.0）
2. 检查所有模块是否适配新 Core
3. `node 发布.js --force`

## 备份

每次发布，变化的模块会被压缩到：

```
backup/{模块名}/{模块名}_{日期}.zip
```

**永久保留，不删**。

## 日志

`build/发布日志_{时间戳}.txt`。

保留最近 50 个。

## 清单

`build/发布清单.md`：本次发布的模块状态表。

## 数据文件更新

**改 productMap.js / commonLocations.js 不用发版本**。

直接 push `main` 分支即可：

```bash
cd git
git add .
git commit -m "更新数据"
git push origin main
git push github main
```

**用户刷新页面拿到最新**（CDN 会缓存，可能延迟几分钟到 1 小时）。

**清单更新同理**（`src/js/modules.js`），走 main。
